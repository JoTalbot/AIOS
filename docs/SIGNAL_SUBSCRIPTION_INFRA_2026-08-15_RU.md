# Q4+Q5: модель очереди исполнения + инфраструктура подписки на сигналы

**Дата:** 2026-08-15 | Ветка: agent/20260815-quant-oos-profit

## Q4 — Модель очереди исполнения (mm_proto_backtest.py)
- `--queue-model`: при пересечении mid квоты филл ЧАСТИЧНЫЙ — наша доля в уровне
  = quote_size / (quote_size + other_size_at_level); остаток остаётся в очереди
  и добирается на следующих снапшотах (реалистично для maker-ордеров);
- проверено на ws-данных (1Гц) с РЕАЛЬНЫМИ спредами: BTC 0.0016 bps, ETH 0.053,
  SOL 1.32 — с реалистичными half-spread (0.001-0.05 bps) квоты исполняются 9-14 раз/час;
- ВАЖНЫЙ УРОК: прежняя настройка half-spread 2bps в ~1000 раз шире реального спреда
  BTC — квоты не исполнялись никогда. Реальный MM встаёт на лучшие цены.
- PnL на 1-1.6ч ws-данных всё ещё отрицательный (мало данных для вердикта) —
  инструмент готов, данные копятся.

## Q5 — Инфраструктура подписки (сигнальный продукт)
- `data/quant_subscriptions.json`: подписчики (token, chat_id, tier, expires, active);
- `scripts/subscription_manage.py`: add/list/revoke/clean (токены secrets.token_hex);
- эмиттер (`mm_signal_emitter.py`) теперь РАССЫЛАЕТ сигналы владельцу + всем активным
  подписчикам (`broadcast`); проверено: broadcast to 1 chats (owner-подписка 365 дней);
- продукт готов к активации: после подтверждения точности (>=65-70% на движениях
  за 2-4 недели) — создать подписки для клиентов, установить цену/лимиты.
