# Протокол скиллов, исследований и видимости статуса ИИ-агентов

Статус: **обязательный** для людей, автокодера и внешних ИИ-агентов (дополняет `AGENTS.md`
и `coordination/README.md`, не заменяя их). Ответственный: @JoTalbot.

Дата введения: 2026-08-25. Ветка `agent/20260825T074311Z-openhands-skills-protocol/agent-skills-protocol`.

## 1. Кому и зачем

Репозиторий изменяется с разных машин разными ИИ-агентами параллельно. У каждого агента
свой контекст, который исчезает после сессии. Этот протокол делает три вещи:

1. **Статус виден другим** — любой агент за минуту понимает, кто и на каком шаге работает.
2. **Опыт не теряется** — лог сессии дистиллируется в основной скилл агента.
3. **Колёса не изобретаются** — перед каждым шагом ищется подходящий скилл (локально и в
   интернете) и проводится глубокое исследование источников.

## 2. Протокол видимости статуса («Текущий шаг»)

- У каждой сессии есть свой журнал `coordination/sessions/<session-id>.md` по
  `coordination/SESSION_TEMPLATE.md` (один файл = одна сессия/агент).
- В журнале обязателен блок `## Текущий шаг (виден другим агентам)`: одна строка — что
  выполняется сейчас и какой результат ожидается.
- Блок обновляется **после каждого существенного рубежа** (не реже, чем перед паузой),
  синхронно с `updated_utc` во frontmatter.
- Перед стартом своей задачи агент ОБЯЗАН прочитать «Текущий шаг» всех журналов со
  статусами `ACTIVE`/`PAUSED` и claims из `coordination/claims/`. Пересечение scope —
  стоп и разделение ответственности по `coordination/README.md`.
- На паузе/завершении «Текущий шаг» заменяется итогом: завершённая точка + один
  конкретный следующий шаг (или `нет`).

## 3. Протокол обязательного поиска скиллов

Перед каждой задачей и перед каждым кодо-/конфигурационным шагом:

1. **Локальный каталог:** `skills/<категория>/<skill>/SKILL.md`, сводка —
   `skills/SKILLS_INDEX.md`, машинный индекс — `skills/index.json`. Ищется по названию,
   trigger-полям и описанию.
2. **Интернет-каталоги:** общедоступные репозитории скиллов агентов (например, каталоги
   skills для OpenHands/Claude/Codex), официальные документы используемого агента.
3. **Решение:** подходящий скилл **применяется**, либо в журнал пишется явный отказ
   («отклонён: причина»). Молчальный отказ запрещён.
4. **Пустой результат:** если подходящего скилла нет — шаг выполняется, а по завершении
   создаётся новый скилл по разделу 4.

Скилл не легализует нарушение золотых правил `AGENTS.md` (protected-файлы, секреты,
минимальные правки).

## 4. Протокол дистилляции лога в скилл («лог → основной скилл агента»)

По завершении сессии (status `DONE`/`PAUSED`) агент ОБЯЗАН:

1. Собрать из журнала полезное: устоявшиеся находки, причины ошибок, сработавшие
   команды/параметры, ловушки и как их обошли, критерии проверки.
2. Записать скилл `skills/<agent>/<task-slug>/SKILL.md` по `skills/TEMPLATES/SKILL.md.template`
   (frontmatter: `name`, `description`; тело: Описание, Алгоритм, Контроль и развитие).
   Кратко и проверяемо; без секретов и сырых логов.
3. Повторяющиеся темы — обновлять существующий скилл, а не плодить дубликаты
   (правило аналогично auto-lesson из `scripts/memory_to_skills.py`).
4. Журнал остаётся историческим источником; скилл — рабочей памятью следующих агентов.
   Ссылку на скилл записать в журнал сессии (раздел «Изменённые файлы»).

## 5. Протокол глубокого исследования перед каждым шагом

Перед каждым шагом, меняющим код или конфигурацию:

1. **Интернет-исследование:** официальная документация затронутых библиотек/протоколов,
   issues/PR аналогичных проектов, свежие материалы по теме. Предпочтение — первичным
   источникам; агрегаторы — только входная точка.
2. **Исследование репозитория:** код и runtime — источник истины. Перед шагом найденные
   извне предположения сверяются с фактическим кодом/конфигом/сервисами. Расхождения
   фиксируются в журнале (правило «факты из кода/runtime имеют приоритет»).
3. **Фиксация:** 1–3 строки вывода в журнал (раздел «Ход работы и решения»): что искали,
   что нашли, как это меняет шаг.
4. **Запрет:** в исследовательских итогах — никаких секретов, токенов, персональных
   данных (см. «Правила безопасности» в `coordination/README.md`).

## 6. Быстрый чеклист агента

- [ ] Прочитаны AGENTS.md, coordination/README.md, PROJECT_CONTEXT.md, активные claims.
- [ ] Свой журнал создан; «Текущий шаг» заполнен.
- [ ] Поиск скилла: локальный + интернет; применён или записан явный отказ.
- [ ] Перед каждым шагом — глубокое исследование; итог 1–3 строки в журнале.
- [ ] После каждого рубежа — «Текущий шаг» обновлён.
- [ ] По завершении — лог дистиллирован в `skills/<agent>/<task-slug>/SKILL.md`,
      журнал закрыт, claim удалён по протоколу.

## 7. Связь с другими правилами

- Координация, claims, git-правила и аварийный handoff — `coordination/README.md`.
- Золотые правила, protected-файлы, diff-режим, бюджеты модулей — `AGENTS.md`.
- Формат журнала и статусов — `coordination/SESSION_TEMPLATE.md`.
- Автоматические auto-lesson-скиллы из памяти автокодера — `scripts/memory_to_skills.py`
  (этот протокол дополняет их ручной дистилляцией от любого агента).
