# Самозащита AIOS (self_protection.py + selfguard)

## Protected-файлы — НЕ выбирать их для правок

Канонический список: `aios_core/self_protection.py::PROTECTED_PATTERNS`
(зеркало — раздел в AGENTS.md). Если задача требует protected-файл —
пропусти задачу и выбери соседний незащищённый модуль для того же эффекта.

## Что отклоняется автоматически (apply/validate)

- Сокращение файла >50% (для файлов >30 строк) — «выедание»
- Исчезновение ≥60% функций/классов модуля
- ≥60% тривиальных тел (`pass`/`...`) вместо реализации
- `eval(`/`exec(` в новом коде
- Почти-пустой файл (<10 строк кода после правки)
- SyntaxError, поломка `import aios_core`
- Новые падения таргетных тестов (pytest-gate)

## Дозированное «не лезь»

- Укорочение ≠ улучшение. Не «чисти» чужие модули от «лишних» строк.
- Массовые удаления (>3 файлов) = инцидент, откат + алерт в Telegram.
- Watchdog (aios-selfguard.service) восстанавливает protected-файлы из
  снапшота: скрытая правка protected всё равно будет стёрта.
