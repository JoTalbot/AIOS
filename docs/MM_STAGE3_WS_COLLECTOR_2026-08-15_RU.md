# MM этап 3: websocket-коллектор глубины — запущен

**Дата:** 2026-08-15 | **Скрипт:** `scripts/collect_orderbook_ws.py`
**Сервис:** `aios-orderbook-ws.service` (active, Restart=always)

## Что делает
- Подписка на Binance public partial depth (`<sym>usdt@depth20@100ms`), 20 уровней стакана;
- отдельное соединение на пару (BTC, ETH, SOL) — надёжно, без конфликтов recv;
- запись самого свежего снапшота раз в 1 сек в `data/quant/orderbooks.sqlite`,
  таблица `snapshots_ws` (схема как `snapshots` + source='binance_ws');
- автопереподключение при обрыве (reconnect 5s), ping-keepalive 20s.

## Статус
- Сервис active, 3 пары подключены, данные пишутся (~1.75 снапшота/с суммарно).
- За ~2 мин накоплено 329 снапшотов; спред BTC ~0.002 bps (реальный), глубина ~$700k.
- Цель: ≥2-4 недель данных для реалистичной MM-симуляции (частоты ~1 Гц вместо 9с).

## Зачем
Предыдущая симуляция использовала REST-снапшоты с интервалом ~9с — слишком редкие
для репрезентативной оценки исполнения. Websocket-поток (100мс у Binance) позволяет
накопить качественный след стакана для: (а) переобучения микроструктурного сигнала;
(б) реалистичной симуляции очереди/частичных филлов; (в) итогового вердикта по MM.
