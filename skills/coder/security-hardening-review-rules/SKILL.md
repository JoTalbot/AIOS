# Security-изменения: правила ревью (боевые отказы 02.08.2026)

Прежде чем «улучшать безопасность» модуля — проверь себя по этим правилам.
Каждое нарушение уже приводило к отклонению целой ветки при ручном мерже.

## Запрещённые приёмы (security theater)

1. **Выдуманные импорты.** `from aios_core.security.security_policy import Authenticator`
   — такого класса не существует, модуль кирпичится при импорте. ПЕРЕД импортом проверяй
   реальность символа: `grep -n "class Имя" целевой/модуль.py`. То же для get_logger и
   BaseSettings из pydantic (v2: только pydantic-settings).
2. **`extra="forbid"` на pydantic-схемах HTTP-запросов** (WebRequestSchema и т.п.) —
   API начнёт отклонять легитимные запросы с дополнительными полями. Для Settings —
   только `extra="ignore"` (чужие переменные .env не должны валить импорт).
3. **Глобальный html.escape тела запроса на ВХОДЕ** — порча пользовательских данных и
   двойное экранирование. Санитайз применяй только на отображении (output), не на приёме.
4. **X-XSS-Protection** — заголовок deprecated. Падать при значении «0» или требовать его —
   вредно: современная практика обратная (0 / отключить legacy-аудитор, полагаться на CSP).
5. **Обязательная env-переменная в `__init__`** (raise, если не задана) — ломает все
   существующие вызовы и импорты. Секреты бери из env с безопасным дефолтом либо ошибкой
   в точке использования, не в конструкторе.
6. **Regex-детект XSS поверх html.escape** — защита уже обеспечена экранированием;
   дополнительные regex-паттерны — ложные срабатывания и риск ReDoS.
7. **Замена семантики существующих полей** (masked_payload → encrypted payload) — ломает
   контракт данных для всех потребителей. Новое поле добавляй рядом, старое не переопределяй.

## Разрешено и приветствуется

- Валидаторы pydantic v2 на конфиге: `field_validator`, `Field(ge=..., le=..., pattern=...)`.
- Логирование security-операций с маскировкой значений (первые/последние 4 символа).
- Удаление мёртвого кода с секретами — после проверки 0 ссылок / 0 процессов / 0 юнитов.
- Секреты из `os.environ` с понятным поведением при отсутствии.
- Сканирование hard-coded секретов — через `scripts/secrets_scan_repo.py`.
