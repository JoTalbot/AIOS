# Жизненный цикл OLX-продажи и ТТН

## Состояния

```text
pending (данные покупателя собраны)
  └─ ТТН создана → awaiting_shipment
       ├─ товар физически на складе, но `reserved_qty` уменьшает доступный остаток;
       ├─ `sale_state = sold_awaiting_shipment`;
       └─ создана задача «Отправить товар по ТТН».

awaiting_shipment
  └─ владелец пишет «отправил <ТТН>»
     или НП подтверждает приём → in_transit
       └─ резерв списывается из физического `qty`.

in_transit
  ├─ НП/владелец подтверждает доставку → delivered
  │    └─ сделка закрыта; сумма записывается в `data/finance.json` ровно один раз.
  └─ НП/владелец подтверждает возврат → returned
       └─ создаётся задача физически принять возврат.

returned
  └─ владелец пишет «получил возврат <ТТН>» → return_received
       └─ товар возвращается в складской остаток.
```

Возврат **не добавляется в склад автоматически** по одному только статусу Новой
Почты: это защищает от появления виртуального остатка до фактического получения
товара продавцом.

## Данные и идемпотентность

* `data/sales_lifecycle.json` — сделки и история переходов;
* `data/sales_tasks.json` — открытые/закрытые задачи и расписание напоминаний;
* `data/inventory.json` — физический остаток, резервы и доступный остаток;
* `data/pending_sales.json` — синхронизирован для прежнего OLX/autonomy-контура.

Повторный ответ API о той же ТТН, повторное сообщение «отправил» или «доставлено»
не создают второй резерв, второе списание или второй финансовый доход.

## Команды владельца в Telegram

```text
задачи отправки
отправил 20451502718405
доставлено 20451502718405
вернулась 20451502718405
получил возврат 20451502718405
```

Если открыта одна сделка, можно написать и без номера: `отправил этот товар`.
Если сделок несколько, бот запросит ТТН или точное название детали.

## Автоматическое отслеживание

`run_np_alerts.py`, который запускается существующим systemd-таймером
`aios-np-alert.timer`, дополнительно опрашивает все активные исходящие ТТН через
публичный API Новой Почты. Он:

1. присылает уведомление только при смене статуса;
2. переводит товар в доставку, когда НП подтверждает приём;
3. закрывает сделку при успешной доставке;
4. создаёт задачу принять возврат при возврате;
5. напоминает о неотправленном товаре, пока задача открыта.

Интервалы напоминаний:

* `AIOS_SHIPMENT_REMINDER_MINUTES` — по умолчанию 120 минут;
* `AIOS_RETURN_REMINDER_MINUTES` — по умолчанию 360 минут.

Для переноса ранее созданных ТТН используется:

```bash
python run_sales_lifecycle.py migrate
```
